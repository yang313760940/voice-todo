# 0001 · 起点：零基础，走通第一条循环的模型

- 日期：2026-11-04
- 状态：进行中

## 背景 / 起点

YG 完全零开发基础，没有编程背景。学开发的目的是「学会开发本身」，App（语音提醒/待办/四象限/番茄）是载体而非终点。主线定为「AI 写代码，YG 做决策与验收」，但要能读懂代码。时间不固定 → 课程必须极短、可断点续学。

仓库已有（非代码）：
- `docs/requirements-interview.md`：Q1–Q24 需求访谈，仍有若干「待明确」项。
- `GLOSSARY.md`：领域术语表（事项/提醒/四象限/番茄/清单等 + 避免的同义词）。
- `AGENTS.md` + `docs/agents/*`：GitHub backend 的 issue/triage/domain 规范。
尚无任何代码、issue、地图。

## 教了什么 / 决定

- 第 1 课：五步循环模型（想清楚→拆小→做一块→验一块→复查，回到第一步）。目的是先给一张能挂住后续所有技能的“地图”。
- 第 2 课：issue = 小任务卡；四个零件（标题/目的/验收标准/边界），验收标准是灵魂。
- 建立 `reference/glossary.html`：核心术语速查。
- 建立共用组件 `assets/course.css`（Tufte 风格）与 `assets/quiz.js`（即时反馈测验）。

## 关键决策

- 先建“心智模型”再建“操作”。不第一课就上手命令，避免淹没初学者。
- 每课一个可完成的胜利，配即时反馈测验（存储强度 > 熟练感）。
- 用 YG 自己的真实需求（Q14 五个入口、Q24 离线识别等）做所有例子。

## 下一步（zone of proximal development）

- 第 3 课：真的在他仓库里用工具链建出第一张 GitHub issue（用 Q14 的「五个入口」），让他亲手按下“建”。→ 把第 2 课的知识变成一次真操作。
- 之后：triage 一张票 → 用 grilling 处理「待明确」项 → 走一遍 tdd 的红-绿。

## 观察 / 风险

- 完全零基础，任何安卓/命令行概念都要提前埋线解释。
- 「待明确」项很多，可作为后续 grilling 与拆分实战素材，天然贴合 mission。
