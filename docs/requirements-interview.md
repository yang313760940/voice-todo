# 安卓语音提醒应用：需求访谈记录

状态：2026-11-04 已按用户 /to-spec 指令整理并发布首版规格。正式规格为 [GitHub #1](https://github.com/yang313760940/voice-todo/issues/1)，标签 ready-for-agent。本文件保留访谈决策来源，工程实施与验收以正式规格为准；本轮未开始应用开发。

补充状态：2026-11-06 开始语音添加改版访谈，见文末。该节记录本次新决定及待确认问题；尚未形成完整新版规格、同步 GitHub 规格或修改业务代码，不能将下文首版历史决定当作本次改版结论。

## 已确认决定

### 第一轮 Q1—Q7

- 个人安卓应用，第一版免登录，事项本地保存，暂不加入团队协作或多设备同步。
- 语音转写后由在线 AI 生成可编辑事项草稿，展示识别文字供核对；用户确认后创建。含糊时间需要补充确认。
- 默认通知、提示音、振动；单项可开启朗读及持续响铃。锁屏默认隐藏具体内容。
- 事项可不设时间，仍可进入四象限。
- AI 建议初始象限，用户最终决定；拖拽不改变提醒时间，临近时间不自动迁移象限。
- 番茄支持绑定事项或独立计时；默认专注25分钟、短休息5分钟、每4次专注后长休息15分钟，均可调整；番茄结束不自动完成事项。
- AI 联网解析，断网可手动添加、管理事项、执行已安排提醒与番茄计时。语音转写联网边界已在Q25—Q26确认：首版录音仅本机处理。

### 第二轮 Q8—Q13

- 一句话可拆分多条草稿，逐条编辑或删除后批量确认；时间未确定时补充或明确不设提醒。
- 重复规则包括每天、每周指定星期、每月指定日期。区分完成本次与结束整个重复事项；月末缺少对应日期时采用当月最后一天；工作日暂按周一至周五。
- 提醒支持完成、延后、关闭本次提醒；关闭不完成事项。延后选项为10分钟、30分钟、1小时及自选时间。持续响铃默认最多1分钟，随后保留通知。
- 提醒时间与截止时间独立、均可留空。仅有明确截止时间的事项标记逾期；已触发提醒标记已提醒；两者均不自动改变象限。
- 番茄支持暂停、继续、提前结束；专注与休息各阶段手动开始。完整结束专注才计完成番茄；提前结束保留实际专注时长但不计完成数。锁屏或切换应用后继续计时。
- 点击麦克风开始、再次点击结束，转写文字可修改，保留文字输入；首版优先普通话。失败时保留已取得文字并支持手动创建；录音默认不长期保存。

### 页面结构 Q14—Q17

- Q14 用户明确修订：首页为类似滴答清单的正常待办列表；四象限、番茄计时和我的分别独立成页。
- 底部固定导航：待办、四象限、番茄、我的。
- 首页默认今天，提供收集箱、今天、最近七天、全部、已完成入口；支持自建清单，如工作、生活、学习。收集箱采用Q18确认后的定义：未分类事项，而非所有无时间事项。
- 清单表示事项归类，象限表示重要性与紧急性；各视图引用同一事项并同步修改。
- 待办和四象限均支持添加，待办页保留醒目语音入口；详情编辑名称、时间、提醒方式、清单与象限。
- 我的分组包括提醒设置、番茄设置、外观设置、语音与AI、权限与提醒检查、数据管理、关于软件。首版无需头像及个人资料。
- 提醒设置：提示音、振动、朗读、持续响铃、延后时长。
- 番茄设置：专注、短休息、长休息时长及长休息间隔。
- 外观设置：浅色、深色、跟随系统及字体大小。
- 语音与AI：识别语言、联网解析说明。
- 权限与提醒检查：通知、麦克风及提醒所需权限状态与处理引导。
- 数据管理：手动导出备份及导入恢复。
- 关于：版本信息与隐私说明。

### 第三轮 Q18—Q24

- Q18：新增计划日期，与提醒时间、截止时间分开；只有日期时不自动安排响铃。今天视图汇总当天计划、当天提醒、当天截止及逾期事项，按事项去重。收集箱为未分类事项入口，可筛选未安排时间；此定义替代此前“未安排时间事项进入收集箱”。
- Q19：一个事项支持多个指定时刻提醒及相对截止时间提醒；截止时间修改仅带动相对提醒。完成后取消未触发提醒，重复事项只影响本次。
- Q20：重复事项每次独立记录，漏做不阻挡下一次；编辑可选仅本次或本次及以后，保留历史；同一重复事项积压记录折叠。
- Q21：手动添加默认不重要不紧急，AI草稿显示建议；完成事项进入已完成，可恢复。恢复时若旧提醒时间已过去，提示重新安排。
- Q22：同一时间只运行一个番茄，切换事项先结束当前专注；暂停不计时；退出后根据预定结束时刻恢复，到点则显示结束待确认，不自动开始下一阶段。展示今日完成数、今日专注时长和最近七天记录。
- Q23：首版导入备份采用替换，预览备份日期与事项数量，导入前自动保留当前数据恢复副本。备份含事项、清单、专注记录、偏好；不含录音及服务密钥，权限重新授予。
- Q24 用户原话：“Q24 第一版交付先使用离线识别，后期再增加在线识别\n其他按推荐”。首版语音识别必须离线，后期增加在线识别；替代之前优先依赖手机系统服务的建议。APK及源码交付、个人配置AI服务的方案仍需明确确认，避免将对其他题的认可扩大至Q24全部内容。

### 第四轮 Q25—Q29

- Q25：录音在手机内转成文字，仅文字发送在线AI。断网仍可转写并手动填写字段创建事项；显示尚未经过AI整理。用户主动选择手动创建或稍后重试，网络恢复不自动发送积压文字。
- Q26：普通话离线识别引擎与模型随安装包交付，首次安装无网络也可识别；接受安装包体积增加。具体模型、大小、性能和许可证在实施选型时核实。
- Q27：交付个人使用APK及完整源码；用户在高级设置填写AI服务地址、模型和密钥，费用按所选服务用量结算。未配置AI仍可使用离线语音、手动创建、提醒、四象限及番茄。
- Q28：开机后汇总错过且未完成的事项，不逐条连续响铃；保留原计划时间，由用户选择完成或重新安排。重复提醒跟随手机当地时间，一次性提醒保持原定实际时刻，跨时区后显示对应当地时间。
- Q29：回收站保留30天；删除重复事项可选仅本次或本次及以后，取消对应提醒，保留历史专注记录；恢复时过去的提醒需要重新安排。删除清单默认将事项移回收集箱。

## 技术事实与验证边界

- 官方资料研究已完成，见 research/offline-speech.md。系统优先离线标志不足以保证纯离线，首版采用内置引擎及模型路线；尚未下载模型、构建APK或真机验证。
- 安卓提醒受通知、精确闹钟权限及系统后台限制影响；权限检查应明确显示当前状态。强制停止或关机期间的实时响铃不作为承诺；恢复规则按Q28。

## 后续澄清与规格归档

- 用户强调通知提醒和闹钟提醒的高可靠性，并进一步明确：“全版本支持不包括老旧的设备，andriod 10以下不用适配”。最低版本确认Android 10（API29），覆盖Android 10及以上；优先推荐原生Kotlin与Jetpack Compose，UI与闹钟核心分离，具体技术栈仍为建议。
- 后续安卓新版本持续跟进适配，不将未发布系统视为已验证兼容；各支持版本与主要品牌需建立真机验收矩阵。
- 兼容目标需要分别覆盖：最低安装版本、目标SDK行为、CPU架构与离线模型支持、通知/精确闹钟/全屏通知权限、各品牌后台策略。通知与闹钟两个提醒模式分别验收，不以界面框架或后台常驻替代系统闹钟机制。
- 已确认功能全部进入首版实施范围，不将在线语音识别、账号同步或团队协作纳入首版。
- 用户已通过 /to-spec 要求综合当前上下文生成规格；正式规格采用原生Kotlin与Compose作为工程基线，并包含测试入口、行为验收、实施边界和待实测项目。后续先拆分可独立验收的实施票，当前未开始应用开发。

## 2026-11-06 语音添加改版访谈（已确认，规格见 #30）

可点击逻辑预览：本机可视化目录的 `voice-capture-preview.html`（示意实现，不是产品代码）。规格已发布为 [issue #30](https://github.com/yang313760940/voice-todo/issues/30)。

### 已确认方向

- 将待办页顶部语音添加入口移到下方四个导航 tab 的正上方，只展示语音图标。用户澄清“文字添加”的含义：语音识别完成后，在识别文字的末尾增加小笔图标，点击后手动修改识别文字；不是此前建议的输入面板内键盘切换入口。不再沿用顶部独立“文字添加”按钮作为本次文字编辑入口；无需录音的纯文字创建复用小笔入口，规则见下文。
- 从离线语音识别改为在线语音识别，并根据语音内容自动填写事项详情，参考滴答清单的语音添加体验。此方向取代首版“语音必须离线、录音不上传”的边界；供应商范围见下文，具体模型、上传告知及失败处理尚未确定。
- 用户原话：“说完之后自动填好，等待2秒钟后自动保存”。正常流程为说完后自动填写草稿，填写完成后等待 2 秒自动保存为正式事项，不再要求每次手动点击保存。此决定取代本次语音添加流程中“用户确认后才创建”的首版要求，不扩大到文字添加或已有事项编辑。
- 用户原话：“没有具体时间提醒的事项先全部收集到收件箱，后面我手动在设置每个事项的提醒时间”。沿用应用名称“收集箱”：语音事项未提供具体提醒时间时，包括只说“明天下午”等含糊时段，填写完成后仍等待 2 秒自动保存到收集箱，不设置提醒，之后由用户逐项手动设置。单纯缺少具体提醒时间不再要求补充后才能保存，AI 不代猜提醒时刻；本条是语音添加的归集规则，不将收集箱重新定义为仅包含无时间事项。
- 用户确认：在两秒等待期间点击草稿开始修改，即取消本次自动保存，修改完成后由用户手动保存；不会在编辑过程中继续倒计时，也不会编辑结束后自行恢复自动保存。
- 小笔图标编辑的是识别文字，不是直接编辑标题或提醒字段；点击小笔开始编辑同样适用取消本次自动保存的规则。
- 用户确认：修改识别文字后，点击“修改完成”触发 AI 根据新文字重新整理并更新事项及提醒时间等字段；新结果仍需用户手动保存，不重新启动两秒自动保存。例如将“三点”改成“四点”，重新整理的提醒时间应反映修改后的原意。
- 用户确认保留备用纯文字入口：点击首页麦克风打开输入面板，即使没有识别文字也显示小笔图标；不用先说话或成功识别即可点击小笔，停止正在进行的录音并弹出键盘直接输入。已有文字时小笔用于修改，无文字时用于从空白输入；首页仍只展示麦克风，不恢复独立文字添加按钮。纯文字输入不因本次决定获得两秒自动保存行为。
- 用户确认两阶段自动流程：在线语音识别负责将声音转成文字，边说边显示；录音结束后，程序自动将最终识别文字交给在线 AI 整理，填写事项及相关安排，随后按已确认规则保存。用户只需说一次，无需另外点击“AI 整理”。复用现有文字整理与草稿能力，不采用直接由单个多模态模型从音频生成事项字段的路线；供应商范围见下一条，具体模型尚未选定。
- 用户最新明确：“使用使用豆包或者阿里云转文字，然后豆包或者阿里云再填好事项”。语音转写和事项整理两个阶段的供应商范围均为豆包、阿里云，取代此前评估 DeepSeek 以及建议“豆包识别 + DeepSeek 整理”的方向；DeepSeek 不纳入本次新流程。不因此删除原有自定义 AI 配置或已有用户数据。
- 用户确认供应商联动：设置中只选择一次豆包或阿里云，同一家负责语音转写与事项整理，不提供两个阶段的跨供应商组合。两个阶段仍调用各自对应的接口，不意味着一个模型或一把密钥即可覆盖两步；所需凭据与具体模型需核实，首次选择规则见下文。
- 用户明确要求自动结束录音，原话：“自动结束录音，当2秒内检测没有音频输入后就自动识别文字，自动填写提醒事项”。正常说话流程在连续两秒没有继续说话后自动结束录音，取得最终转写结果并自动整理事项，不要求用户点击停止；取代此前手动结束录音的建议。录音期间仍实时显示转写文字。结束录音的两秒静默与填写完成后自动保存的两秒等待是两个独立阶段，中间还有转写收尾和 AI 整理耗时，不能承诺说完两秒内已保存。
- 用户确认：打开输入面板后，如果始终没有开始说话，最多等待 10 秒就停止录音，不创建空事项，保留面板及小笔入口供用户直接打字。这是首次说话前的等待上限；已开始说话后适用连续两秒静默结束录音的规则。
- 用户确认多事项保存方式：一次语音包含多件事时拆成多条草稿，全部填写完成后统一等待两秒并整批保存；各事项分别按有无具体提醒时间处理，不将一条事项的时间自动套给其他事项。例如“明天上午九点提醒我开会，还有买牛奶”拆成开会与买牛奶，前者设置提醒，后者存入收集箱且不设提醒。等待期间只要开始编辑任意草稿或识别文字，就取消整批自动保存，修改完成后由用户手动保存。
- 用户确认 AI 整理失败的处理：已经取得识别文字、但第二阶段整理失败时，保留识别文字并提示“整理失败”，不自动保存，也不设置提醒。用户可点击“重试”再次整理，或手动选择“存入收集箱”，将文字作为一条事项保存且不设提醒。此规则不等同于第一阶段语音转写失败。用户进一步确认：点击“重试”并整理成功后只展示结果，由用户手动保存，不重新启动两秒自动保存，与修改识别文字后重新整理的保存规则一致。
- 用户确认断网或第一阶段语音转写失败的处理：停止录音，保留已取得的识别文字并提示结果可能不完整；不自动填写事项、不自动保存，也不自动切回离线识别。用户可点击小笔补充文字，手动存入收集箱且不设提醒；没有识别文字时也保留已确认的空白输入入口。网络恢复后不自动重试。
- 用户确认中途离开应用的处理：录音、AI 整理或等待保存期间，切换到其他应用或锁屏时停止录音、取消本次自动保存，保留已获得的文字和草稿；应用进程仍存活时，返回后由用户手动继续或保存，不自行恢复倒计时。已经保存成功的事项及提醒不受影响。进程终止后的草稿恢复不在本次范围内，见下文用户决定。
- 用户确认新增独立备注字段：AI 根据输入内容将地点、准备材料等补充说明填写到备注中，用户也可手动修改，不将所有细节塞入标题。例如“明天上午九点提醒我开会，会议室在三楼，记得带报价单”整理为标题“开会”、提醒“明天上午九点”、备注“会议室在三楼，记得带报价单”。这是新增需求，尚未修改数据模型或业务代码。
- 用户确认日期信息保留规则：语音中有明确日期但没有具体提醒时刻时，事项存入收集箱、不设提醒，仍保留计划日期；“下午”等不具体到时刻的时间表述保留在备注中，不猜测具体几点。例如“明天下午拍视频”保留计划日期“明天”、备注中的“下午”安排，明天也出现在“今天”列表，但不会响铃。收集箱归类与计划日期筛选可以同时成立，不将保留日期等同于设置提醒。
- 用户确认麦克风入口的页面范围：只在“待办”页底部、四个导航 tab 正上方固定显示；待办页切换今天、收集箱及其他清单时均保留。四象限原有添加入口不动，番茄和我的页不新增麦克风。
- 用户确认增加自动保存后的撤销功能：保存成功后显示“已添加 N 项 · 撤销”，保留 5 秒。点击撤销会撤回本次整批新建事项、取消对应提醒，并恢复为可编辑草稿；修改后由用户手动保存，不恢复自动倒计时。提示消失后，仍可从事项详情修改或删除，不影响本次添加之外的事项。
- 用户确认个人凭据、本机直连方案：在“我的 → 语音与 AI”选择豆包或阿里云并填写自己的开发者 API 凭据；凭据在手机本地加密保存，应用直接调用所选服务，费用计入用户对应的服务账号。不额外搭建中转服务器，不将共享密钥打包进安装包。具体架构边界见 [ADR-0001](adr/0001-personal-credentials-direct-cloud-access.md)；该确认不代替首次上传告知或供应商数据保留政策核查。
- 用户确认隐私规则：首次使用所选服务时明确提示“录音和文字将上传至豆包／阿里云”，取得同意后才开始上传。仅发送本次录音、输入文字及解析所需的当前时间和时区，不上传历史事项。本机不长期保存录音；云端是否保留及保留多久，以所选服务实际条款为准，不承诺云端完全不留存。此确认是应用的设计要求，不代表已验证供应商的数据保留政策。
- 用户确认明显无效时间的处理：例如识别出“2 月 30 日”时，标出问题并暂停整批自动保存，不擅自改成其他日期；用户可修改，或明确选择将问题事项存入收集箱且不设提醒，之后手动保存整批。该情形不同于未提供具体提醒时间，不能直接套用缺少时间时的自动保存规则。
- 用户确认默认清单归属：有明确提醒时间但未指定清单的事项，在“工作”等自建清单中录入时归入当前清单；在“今天”等汇总视图中录入时归入收集箱，同时按时间出现在对应日期的列表。没有具体提醒时间的事项仍全部进入收集箱，不因录入时位于某个自建清单而改变。
- 用户确认语音指定清单的规则：有明确提醒时间且语音明确指定已有清单时，归入指定清单，优先于当前页面的清单；例如“明天上午九点提醒我开会，放到工作清单”归入已有的“工作”清单。指定清单不存在时提示用户并暂存收集箱，不自动新建清单。没有具体提醒时间时，即使指定了清单，仍按此前规则先进入收集箱。
- 用户确认已过去提醒时间的处理：例如当前下午四点，输入“今天下午三点提醒我开会”时，暂停整批自动保存并提示时间已过；用户需修改，或选择不设提醒并存入收集箱，之后手动保存。不擅自改成明天，也不因录入了过去的提醒时间而立即响铃。
- 用户确认单次录音上限为 60 秒：正常说完仍按连续两秒静默自动结束；达到 60 秒上限时停止录音、整理已有内容，并提示“已达录音上限，内容可能未说完”，改为用户手动保存，不启动两秒自动保存。达到时长上限不视为用户已经完整说完；转写或整理失败时仍遵循各自已确认的失败处理规则。
- 用户明确不需要应用被系统关闭或手机重启后的未保存草稿恢复功能。本次不为此持久化临时识别文字或事项草稿，也不提供重启后的“有未完成的录入”提示；进程终止后，未保存内容不恢复。此前正常切后台或锁屏、进程仍存活时临时保留内容的规则不变，已正式保存的事项及提醒不受影响。
- 用户确认录音面板布局：参考所附第二张截图，从底部弹出；上方显示识别文字，末尾放小笔图标，下方显示波形和录音时长，右上角保留关闭按钮。整理完成后在同一面板展示事项摘要，并明确显示“2 秒后自动保存”；此倒计时仅用于已满足自动保存条件的正常流程，不覆盖编辑、失败、重试、达到录音上限等已确认需要手动保存的情形。
- 用户确认点击关闭按钮的处理：立即停止录音并取消本次自动保存；已有未保存内容时提示“是否放弃本次内容”，确认放弃后才清除内容并关闭面板。选择继续编辑则保留内容，改为手动保存，不恢复倒计时；没有内容时直接关闭。本条针对未保存内容，不撤销已经保存的事项。
- 用户确认 AI 自动填写范围：标题、备注、计划日期、截止时间、提醒时间（含多次提醒）、每天／每周／每月等现有支持的重复规则、所属清单及四象限分类。时间与重复规则以用户输入为依据，不凭空添加；象限可由 AI 提供建议，用户可修改。提示音、振动、朗读及持续响铃沿用现有设置，不由 AI 擅自改变。清单归属、缺少具体时间及异常时间的处理仍遵循前述已确认规则。
- 用户确认说话中途改口的处理：明确更正时采用最后更正的内容，例如“明天下午三点开会，不对，改成四点”采用四点，不生成三点和四点两个提醒。若只是“三点或者四点”等无法确定的表述，则标出疑问、暂停整批自动保存，等待用户修改后手动保存；不能将明确改口与未解决的时间冲突混为一谈。
- 用户确认多事项可分别指定不同清单：例如“明天九点开会，放工作清单；明天六点买菜，放生活清单”，两条事项分别归入各自指定的已有清单，全部填写完成后仍统一等待两秒、整批保存。每条事项独立应用清单归属规则，其中没有具体提醒时间的仍进入收集箱；指定清单不存在时沿用提示并进入收集箱、不自动新建清单的规则。
- 用户确认首次服务选择：不默认绑定豆包或阿里云，首次由用户选择并配置凭据，之后记住所选服务。未配置时仍可通过小笔直接打字、手动存入收集箱，但不启动在线录音识别；此规则不代表可以在未配置服务时进行在线 AI 整理。
- 用户确认统一其他退出方式：系统返回键、下滑关闭面板，或尝试切换到其他 tab，均与点右上角关闭一致——立即停止录音并取消自动保存；有未保存内容时先询问是否放弃，选择继续则保留面板和内容、改为手动保存，不恢复倒计时。这些退出方式本身不产生事项；只有此前已保存成功的内容保留。
- 用户确认纯文字录入不自动保存：点小笔直接打字（含无识别文字时从空白输入）后，由用户手动点击保存，不启动两秒自动保存；此前的推断表述据此确认为用户决定。
- 用户确认保留完整手动填写入口：长按首页麦克风打开完整手动添加表单，可填写多个提醒、重复规则等全部字段；短按仍是语音录入。不额外增加悬浮按钮。
- 用户确认移除本机离线语音识别：在线识别确定后，移除内置离线模型与离线转写代码，不再随安装包交付，也不做断网时的离线回退；断网仍按已确认规则只保留手动录入。
- 用户确认原有自定义 AI 配置的处理：新语音流程只提供豆包、阿里云；已保存的自定义 OpenAI 兼容地址、模型和密钥不主动删除，但不再参与语音转写或事项整理，设置页需明确标注为旧配置。
- 用户确认服务设置的入口：在“我的 → 语音与 AI”管理服务选择与凭据；首次点击麦克风时若尚未配置，在录音面板内引导跳转到该设置页，配置完成后返回继续录音。
- 用户确认语言设置：原离线普通话设置随离线引擎失效，改为在线服务的识别语言选项，默认普通话，只列出所选服务实际支持的语言。
- 用户确认语音入口形态：待办页底部、四个导航 tab 正上方居中显示一个悬浮圆形按钮（约 56dp），只有语音图标，不显示文字标签；页面内容滚动时保持可见。
- 用户确认倒计时可取消：两秒自动保存倒计时本身可点击，点一下即取消本次自动保存、转为手动保存；与开始编辑或关闭面板取消自动保存的效果一致，均不留下半成品事项。
- 用户确认保存后不跳转：保存完成后停留在原清单视图，仅在底部提示“已添加 N 项 · 撤销”，新事项按各自归属出现在列表；不自动打开详情页或切换到其他页面。

### 待确认边界

- 实施前的核实项：两家供应商的实际数据保留条款、各接口所需凭据字段、当前可用模型 ID 与计费单价。这些是事实核查，不改变已确认的产品行为。
- 实现时确定的细节：迟到结果的应用内丢弃方式、切换页面时的状态保持范围。已确认的行为是把迟到结果丢弃、不产生事项，不恢复倒计时。
- 其他字段校验失败的统一口径：按同类异常处理，即暂停整批自动保存并提示修改，不擅自修正或丢弃事项；具体提示文案在实施时确定。

### 方案建议与事实（非已确认决定）

- 两阶段流程已获用户确认，见“已确认方向”；具体服务的识别效果、整理准确性与延迟尚未实测，不作效果或响应时长保证。
- 自动结束录音建议以语音活动检测判断连续两秒未检测到说话，而非等待麦克风不再产生音频帧或网络不再返回结果；麦克风静音时仍可能持续输出音频数据。噪声环境下的检测效果需实测；尚未开始说话时的十秒等待上限已确认。
- [滴答清单官方 AI 语音添加说明](https://help.dida365.com/articles/7444666114547646464)（2026-11-06 查阅）描述了提取字段、拆分多条任务、核对后点击保存的体验。两秒后自动保存是本应用的新决定，不是已核实的滴答行为。
- 2026-11-06 核查[火山引擎豆包流式语音识别 API 文档](https://www.volcengine.com/docs/doubao-voice/large-model-streaming-automatic-speech-recognition-api-1)：提供 WebSocket 双向流式语音识别，可用于实时显示转写文字。接入的是开发者语音服务，不是操作豆包 App；具体凭据、可用接口版本和计费仍需在实施前核实。
- 同日核查 [DeepSeek 官方 API 概览](https://api-docs.deepseek.com)及 [Responses API 输入能力](https://api-docs.deepseek.com/guides/responses_api)：可调用文字对话接口；本次未找到官方公开的实时语音转写接口，不能承诺其直接接收录音并实时转写。此前建议由 DeepSeek 整理文字，已被用户最新供应商选择取代，仅保留此条作为评估记录；第三方包装服务不视为 DeepSeek 原生语音能力。

### 接口方案（建议，尚未实现或实测）

两家都按“实时语音识别 → 文字整理”两段接入，均在手机端直连，不经过自建服务器。

| 项目 | 阿里云百炼 | 豆包（火山引擎） |
| --- | --- | --- |
| 实时识别 | `qwen3-asr-flash-realtime` 等，WebSocket 流式，16kHz 单声道 PCM，支持服务端断句 | 大模型流式语音识别 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async` |
| 事项整理 | 千问文本模型，OpenAI 兼容接口，支持 JSON Schema 结构化输出 | 火山方舟文本模型，OpenAI 兼容 `chat/completions` |
| 凭据 | 一个百炼 API Key 覆盖两步 | 语音服务与方舟模型是两套凭据，需分别配置 |

- 建议首个实现选阿里云：一把 Key 覆盖两步、文本侧可用 JSON Schema 约束输出结构，接入面更小；豆包作为第二个适配器，用于对比识别效果。
- 客户端抽象两层接缝：`SpeechStream`（开始／推送音频／静音判定／最终文字／错误）与 `DraftOrganizer`（识别文字 → 事项草稿）。后者复用现有 OpenAI 兼容调用与草稿校验、批量确认能力，避免为两家各写一套整理逻辑。
- 现有代码要求：`AiAssistClient` 目前是“整段文字 → 非流式结果”，需在其上增加流式识别适配，而不是改写现有调用；`OfflineTranscriber` 与内置模型随本次改版移除。
- 模型 ID、计费与限额会变化，实施前须以控制台实际可用项为准；[百炼实时识别文档](https://help.aliyun.com/zh/model-studio/qwen3-asr-flash-realtime)标注北京地域约 0.00033 元／秒，[结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)列出了支持 JSON Schema 的模型系列，[火山方舟 OpenAI 兼容说明](https://ark.volcengine.com/region:cn-beijing/docs/compatible-with-openai-sdk)列出了方舟的兼容调用方式。
