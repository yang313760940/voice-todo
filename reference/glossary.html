五步循环

五步循环the loop
软件开发可以重复执行的循环：想清楚 → 拆小 → 做一块 → 验一块 → 复查，然后回到第一步。你的整个 App 就是这一圈圈跑出来的。（见 第 1 课）

issue（工单 / 票）

issueticket
一件足够小、小到能一次做完、能明确判断“做完没有”的事。四个零件：标题（一句动词）、目的（为什么）、验收标准（怎么算完）、边界（什么不做）。在本仓库里，issue 真实存在于 GitHub 上，用 gh 命令操作。“点麦克风开始录音、再点结束并转写”就是一张好票。（见 第 2 课）

验收标准

验收标准acceptance criteria
issue 里能逐条打勾的检查项：勾满即完成，勾不满就继续改。它把“做完没有”从主观争吵变成客观检查。这是 issue 里最值钱的一栏。

map（探索地图）

map / wayfindermap
当一个目标太大、路线看不清时，先开一张“地图”，把路线拆成若干工单挂在下面，随着探索逐步补全。map 是容器，下面的小票才是活。工具链里用 wayfinder。“整个 App 的路线图”就可以是一张 map。

triage（分诊 / 分类）

triagetriage
给收进来的 issue 贴标签、定状态，决定它是否“信息够了、能开工”。本仓库的五个标签：needs-triage（待评估）、needs-info（等补充）、ready-for-agent（可交给 agent）、ready-for-human（需人做）、wontfix（不做）。定义见 docs/agents/triage-labels.md。

TDD（测试驱动开发）

TDDtest-driven development
先写一个会失败的测试（描述“应该怎样”），再写最少的代码让它通过，最后整理代码。好处：你总有一个客观标准判断“做对了没有”。“点麦克风应开始录音”可以先写成一个测试，再去实现。

测试 test

测试test
一段自动运行的检查代码：给它输入，断言（assert）输出应是某个值。通过=绿，失败=红。它证明“真的按需求工作”，而不是“看起来能跑”。

红-绿-重构

红-绿-重构red-green-refactor
TDD 的三拍：红（写个失败测试）→ 绿（写代码让它通过）→ 重构（在不改变行为的前提下把代码整理干净）。

code review（代码复查）

code reviewreview
回头看一遍改动，两条轴：规范轴（符不符合本仓库写明的编码规范？）和需求轴（符不符合发起它的 issue/spec？）。工具链的 code-review 会并行跑这两条轴再并列报告。这是你“说不 / 说改 / 说继续”的地方。

术语表 GLOSSARY

术语表GLOSSARY / ubiquitous language
项目里每个领域词的唯一定义，防止同一个词各说各话。你仓库根目录的 GLOSSARY.md 已经写了「事项 / 提醒 / 事项草稿 / 四象限」等定义，还有“避免”的同义词。写票、命名、讨论时都要用这里的词。

grilling（拷问）

grillinggrill
让 AI 对你的方案/想法连环发难，逼出没想清楚的漏洞和模糊边界。用在“想清楚”那一步，比独自冥思有效得多。需求访谈末尾那堆「待明确」，正好拿来被 grilling。

commit（提交）

commitcommit
把当前改动打一个快照存进 Git 历史，附带一句说明。像游戏存档：以后能回退到这一刻。一次有意义的改动对应一次 commit。

API Key（接口密钥）

API Key接口密钥
应用调用云服务时出示的秘密凭证；别人拿到它，可能用你的账号消耗额度。它不是阿里云登录密码，也不是管理云资源的 AccessKey ID / Secret。本 App 的阿里云供应商使用百炼 API Key，实时转写与文字整理共用一把。（见 第 6 课与官方说明）

模型与地域

模型 / 地域model / region
模型是完成某种任务的云端能力；地域是服务接入区域，不是手机所在地。这版 App 用 qwen3-asr-flash-realtime 转写，用 qwen-plus 整理；默认连接北京接口，所以应获取北京地域的 Key。不同地域的 Key 与接入地址不能混用。见官方地域说明。
