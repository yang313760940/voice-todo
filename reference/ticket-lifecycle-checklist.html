走完一张票的完整流程

用 #2「最小闭环」这一圈的真实经过复盘。以后任何票、任何项目，照这张卡走。

这一圈的事实 #2 从「拆好的一张小票」走到了「关闭」。中途修了 5 个真 bug、1 个环境坑、1 次假验收把关。下面每一步都是真发生过的，不是教科书。

整个循环长这样（五步 → 回到第一步）

第 1 步 · 想清楚（这张票要什么）

开工前先读票：#2 的四零件——标题、目的、验收标准（6 条可打勾）、边界（"不做 AI、不做重复、真机留 #3"）。验收标准决定什么叫"做完"。

第 2 步 · 拆小 / 认领（谁在做这张）

确认它是 frontier（blocked_by=0、没人认领），然后 gh issue edit 2 --add-assignee @me 认领——把票移出 frontier，别人不重复做。

第 3 步 · 做一块（让 AI 写，你下命令）

在会话里把票交给 AI 实现。你做的是：给边界、看它往哪走、卡住时给准确诊断。这一圈里卡点全在"依赖"和"环境"，不在业务逻辑。

坑 1 · 20 个编译错误其实是 1 个根因。namespace 写错（com.voicetodo.app vs 代码全用 com.voicetodo）→ R 类找不到 → 连锁崩掉整片。修根因，20 个错塌成 0。
经验：报错先看"第一条"，别逐条追。
坑 2 · 缺依赖会伪装成"语法错误"。缺 lifecycle-runtime-compose → collectAsStateWithLifecycle 找不到 → RecordState 比较、Composable 上下文全报错。
经验：一大片"类型/上下文"错误，常是某个 import 符号没解析。
坑 3 · 变量遮蔽。private val app = app as VoiceTodoApp，右侧 app 解析到属性自己 → 类型退化 → app.scheduler unresolved。
经验：属性名别和构造参数同名。

第 4 步 · 验一块（拿硬证据，不接受口头）

验收的唯一标准：能不能指着硬证据说"这就是它"。这一圈里的硬证据：

证据证明什么
单测 XML tests=8 failures=0保存/取消/重开可见/删除取消闹钟
识别输出原文「对我做了介绍啊…嗯」真 wav + 真模型 + 真识别（口水音骗不了人）
wav SHA-256 + 非零占比 0.989不是静音/假数据
模型 81,828,675 B 精确值随包模型完整，非残缺下载
dumpsys alarm tag=ALARM_FIRE真系统闹钟，不是应用内计时器
APK 159,012,328 B构建产物真实
坑 4 · 中文路径坑测试。项目在 E:\AI工程\…，Windows 默认 GBK，test worker 的 classpath 响应文件解析成乱码 → ClassNotFoundException。
解法：建 ASCII junction C:\dev\voicetodo → 项目，从那儿跑 Gradle。
坑 5 · dlopen 找不到 .so。APK 里明明有 so，但 useLegacyPackaging=false 导致安装后没落地 → UnsatisfiedLinkError: libsherpa-onnx-jni.so not found。
解法：useLegacyPackaging=true + manifest android:extractNativeLibs="true"。
坑 6 · assetManager 传错。模型走绝对路径时 OfflineRecognizer(context.assets, cfg) 会 ReadFile 失败。
解法：绝对路径时 assetManager 必须传 null。

第 5 步 · 复查 + 关票（把债还完再销账）

顺序很重要，别跳：

  1. 证据落盘：docs/evidence-ticket2.md（wav SHA256、识别输出、断网报错）。
  2. 核对 git 干不干净：git ls-files | grep onnx\|aar 应为空（大二进制不入库）；git show --stat 看提交带了啥。
  3. 确认大文件判定：78MB 模型 = 一次性产物 → 不入库（用 URL+SHA256 复现）；175KB 测试 wav = 复现必需 → 入库。这是分寸，不是"一律排除"。
  4. commit + push：本地 commit 先干净，再 push；评论里写的 commit 号必须 GitHub 上真能看到。
  5. 写关票评论：逐条验收标准 × 硬证据，一条条对上；声明边界（真机留 #3、不声称已验证）。
  6. 关票：gh issue close 2 --comment "…；真机验收转 #3"。关掉 #2 → #3 自动从"被阻塞"变"可开工"。

这一圈最该记住的 6 句话

①报错看第一条，20 个错常是 1 个根因。
②验收只认硬证据：字节数、SHA256、logcat 输出、测试断言。不认"AI 说完成了"。
③假成功要当场戳穿：模型缺失时的"仪器测试通过"不算数。
④大文件不入 git，复现必需的小资产要入。看它是"一次性产物"还是"复现必需品"。
⑤关票是销账：证据钉死、历史干净、评论可查，才关。先别 push、先别关这种顺序不是啰嗦，是防返工。
⑥环境坑单独记：中文路径、编码、pagefile、ABI——这些不是业务 bug，但会让真 bug 被淹没。
