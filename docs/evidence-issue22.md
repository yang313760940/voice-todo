# Issue #22 实施记录

## 实现

- 待办页默认进入“今天”。`TodoView` 统一表达今天、收集箱、最近七天、全部、已完成与自建清单；`itemsForView(...)` 从同一份事项集合推导各视图，不在页面内复制数据。
- 今天视图汇总当地今天的计划日期、提醒时间、截止时间，并加入全部未完成逾期事项；按事项 id 去重。排序为逾期优先，其次按当天最近的截止/提醒时刻，再按创建时间与 id 稳定排序。
- 最近七天固定为当地今天起连续七个日期（含今天），不按滚动 168 小时计算；今日边界按 `ZoneId` 的当地零点/次日零点判断。
- 收集箱以 `listId == null` 定义，包含已安排计划、截止或提醒的事项；收集箱与自建清单支持“仅未安排时间”筛选，未安排指计划日期、截止时间与全部提醒均未设置。
- 新增自建清单的创建、重命名、删除与详情页归属切换。删除清单时，事项在同一数据库事务内移回收集箱，保留计划日期、截止、提醒、完成状态与象限。
- 首页提供全宽“语音添加事项”和“文字添加”入口，复用既有录音、离线识别、AI 整理、手动详情与保存流程；从自建清单进入添加时默认加入该清单，其余视图默认进入收集箱。添加页可取消，取消会停止录音并清空本次草稿，不产生事项。
- 待办行显示所属清单；完成、恢复、删除、详情编辑与各视图共用同一 `TodoViewModel`/Room 数据，改动后统一定时刷新，跨视图保持一致。

## 持久化

- Room 从 v5 升到 v6：新增 `todo_lists` 表，并为 `todos` 增加可空 `listId` 与索引。
- `MIGRATION_5_6` 不重建 `todos` 表，避免在删除父表时触发 `reminder_deliveries` 的级联删除；升级测试验证已投递提醒记录、象限与提醒安排均保留，旧事项升级后归入收集箱。
- 生成 `app/schemas/com.voicetodo.data.TodoDatabase/6.json`。
