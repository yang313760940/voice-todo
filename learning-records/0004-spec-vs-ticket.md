# 0004 · spec ≠ ticket：#1 显示"可以实施"不代表该执行 #1

- 日期：2026-11-04
- 状态：进行中

## 学习者的问题

"#2 已经开始执行了，现在 #1 提示也可以实施？我需要开始执行 #1 吗？"

## 核实到的事实

- #1：spec，`blocked_by=0 blocking=0`，未认领，OPEN。body 有 `DSH-ISSUE-KIND: spec` 标记。下挂 #2–#24 共 23 张子票。
- #2：ticket，`blocked_by=0 blocking=1`，**GitHub 上仍是 OPEN、assignee 为空**（用户说"已开始执行"，但票面未体现认领，可能在别处动手或仅口头）。
- 全部 24 张仍 OPEN、零 assignee。

## 教了什么（第 5 课）

- 核心答案：**#1 不用"执行"**。"可以实施"是工具对"无阻塞票"的统一提示，不区分 spec/ticket。
- spec vs ticket 四轴对比：回答什么问题 / 大小 / 能否关闭 / 你要做什么 / 父子关系。
- "实施整个 #1" = 把 #2→#24 全部做完关闭，是整个项目终点，非今日动作。
- 一张 ticket 关闭的唯一标准 = **验收标准全绿**；关掉 #2 才解锁 #3 → 演示五步循环"走下一圈"的齿轮。
- 顺手提醒：票面上 #2 仍未认领，"认领"这一步不能省。

## 关键决策

- 把用户的"误会"当作最好的教学素材：spec 当活干是初学者典型坑，正好借真实提示讲清票类型。
- 不代执行任何操作；先纠正认知，再给下一步。
